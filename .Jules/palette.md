## 2026-08-10 - Semantic Form Constraints and Asynchronous Feedback
**Learning:** Using non-semantic elements (like divs) for forms prevents assistive technology from identifying the container as a form and bypasses native browser autocomplete and keyboard/screen-reader focus workflows. Additionally, immediate alert actions on submit buttons without async visual states cause disorientation, whereas a temporary loading transition with a disabled, low-opacity button clarifies the background processing state.
**Action:** Always wrap input aggregates in a semantic `<form>` element, establish clear label-to-input ID associations with `for` and `id`, apply HTML5 constraint validation (`required`), and use resilient async try/finally state patterns on submit controls to preserve control flow and maintain state persistence under simulated network latency.
